# vw アーキテクチャ

## 目標

- Linux / Windows で動く、起動と表示が速い画像ビューワ
- 対応予定形式: BMP, JPEG, PNG, Nikon RAW (NEF), Sony RAW (ARW)
- 形式ごとの対応はプラグインとして追加する（PNG、JPEG、WebP、カメラ RAW に対応済み）

## 技術選定

| 項目 | 選択 | 理由 |
| --- | --- | --- |
| 言語 | Rust | ネイティブ速度、GC なし、Linux/Windows を同じコードでビルドできる |
| GUI | egui (eframe, glow バックエンド) | 即時モードで軽量、起動が速い、パネル構成が簡単。wgpu ではなく OpenGL (glow) を使い起動コストを抑える |
| PNG | `png` クレート | 純 Rust、16bit をそのまま取り出せる |
| JPEG | `zune-jpeg` + `kamadak-exif` | 純 Rust で速い。EXIF の向きはデコード時に画素を並べ替えて直す（縮小画像や幅・高さを見た目の向きで扱えるように） |
| WebP | `image-webp` | 純 Rust。アニメーションはフレームごとに 1 枚として返し（`frame_count` / `decode_frame`）、アプリはマルチフレームのファイルと同じく 1 スロットに並べる。フレームは前のフレームに重ね描きするので、途中まで描いたデコーダと直前の 16 フレームをプラグインが覚え、順に送るときに先頭からやり直さない |
| カメラ RAW | `rawler`（LGPL-2.1、バージョン固定） | 純 Rust で NEF・ARW・RAF・CR2・CR3・DNG を読める。表示はカメラが埋め込んだプレビュー JPEG を使い、プレビューがないとき・プレビューより大きく拡大したとき・操作で頼まれたときだけ現像する（`DecoderPlugin::develop`、`VwImage::develop_size`）。現像は 2400 万画素で数秒かかり、サムネイルやスライドショーに間に合わないため。現像した画像はトーンカーブがなく暗くなるので、明るさ（輝度の中央値）をプレビューに合わせる。API が SemVer に従わないのでバージョンを固定する |

Electron 系（VSCode そのもの）は起動が重いので採用しない。見た目のレイアウトだけ VSCode に寄せる。

## データの流れ

```
ファイル (bytes)
   │  DecoderPlugin::decode        … 形式ごとのプラグイン（別スレッド）
   ▼
VwImage                            … vw が扱う共通メモリ形式
   │  display::to_display          … 階調変換・縮小（別スレッド）
   ▼
DisplayImage (RGBA8)
   │  egui テクスチャへ転送         … UI スレッド
   ▼
画面
```

- `VwImage`（`crates/vw-core/src/image.rs`）
  - 幅・高さ・チャンネル構成（Gray / GrayAlpha / RGB / RGBA）
  - 画素は `U8` / `U16` / `F32` のいずれか。16bit PNG・RAW を 8bit に落とさず保持する
  - `significant_bits`（RAW の 14bit など）
  - メタデータ（グループ・キー・値の並び）
- `DisplayImage`（`crates/vw-core/src/display.rs`）
  - 描画用の RGBA8。ウィンドウ幅/レベル（`DisplayParams::window`）で階調を決める
  - GPU のテクスチャ上限を超える画像は縮小する（今は 8192px。将来はタイル分割）

## プラグイン

`vw_core::DecoderPlugin` トレイト:

- `name()` / `extensions()` / `probe(header)` / `decode(bytes)` / `read_metadata(bytes)`
- `Registry` が中身（マジックナンバー）→ 拡張子の順でプラグインを選ぶ
- ツリーに出すファイルは、拡張子でプラグインが決まるものはそのまま、決まらないもののうち設定の正規表現に合う拡張子のものは先頭を読んで判定する。拡張子が当てにならない形式があるため

現在は静的リンク（`crates/vw-app/src/main.rs` の `registry()` で登録）。
トレイトはジェネリクスなしのオブジェクト安全な形にしてあり、後で C ABI を被せれば
`.dll` / `.so` の動的プラグインにできる。

予定しているプラグイン（クレート候補）:

| 形式 | クレート案 |
| --- | --- |
| BMP | 自作（単純）または `image` の bmp |
| JPEG | `zune-jpeg`（高速） |
| NEF / ARW | `rawler` または `rawloader` + デモザイク |

### ZIP

- ツリーで ZIP をクリック（スロットではダブルクリック）すると、OS の一時フォルダ下の `vw-archives/<プロセス ID>/` に別スレッドで展開し、展開先をツリーのルートとして足し、その中へ移る（`archive.rs`）。ZIP の中を直接読まないのは、ツリー・フォルダ読み込み・監視がすべてファイルパスで動いているため
- 閉じると展開先を消す。終了時にもまとめて消し、異常終了で残ったものは次の起動時に消す
- 対応は普通の ZIP（無圧縮 / Deflate / Deflate64）。パスワード付きと 7z は未対応

## 画面構成（SDI・シングルページ）

```
┌ File  View ──────────────────────────────────────┐
│ Folders │        Images (n 枚グリッド)   │ Metadata │
│         │  ┌────────┐┌────────┐          │          │
│         │  │ slot 1 ││ slot 2 │          │          │
│         │  └────────┘└────────┘          │          │
├─────────┴────────────────────────────────┴──────────┤
│ Log                                                 │
└─────────────────────────────────────────────────────┘
```

- 4 フィールド（フォルダツリー / メタデータ / 画像 / ログ）は View メニューで表示・非表示
- 画像フィールドは n 個のスロットをレイアウト（`viewer.layout`、`layout.rs`）に従って並べる
  - 自動（既定）は正方形に近いマス目で全スロットを 1 ページに、`列x行` を決めると入りきらない分は次のページ
  - ページはアクティブなスロットから決める（ページ番号を別に持たない）
  - ホイール: フォルダスロットは前後の画像。単体のスロットは 1 枚だけ見ているとき（1x1 か最大化）だけ働き、
    ほかにスロットがあれば前後のスロットへ移る（並べて見ているときは何もしない）。左ドラッグ: 移動、右ドラッグの上下: 押した点を中心にズーム
  - ダブルクリック / Enter: 画像のスロットを画像フィールドいっぱいに最大化、もう一度で戻す
  - ← / → / Space: 同じフォルダの前後の画像、PageUp / PageDown: ページ送り（キーはすべて設定で変更可）
  - フォルダスロット: 1 つのフォルダの画像の並び（`viewer::Sequence`）を持ち、その中で前後に送る
  - スライドショー（`slideshow.rs`、P キー）: 最大化したスロットの下に再生バー。経過時間 × FPS でコマを決め、
    間に合わないコマは飛ばす（時間優先）。約 0.5 秒分（2〜24 枚、メモリ上限の半分まで）を先読みし、
    表示中のスロットとは別のスロット番号で読み込みを頼んで結果を取り違えないようにする
- フラグとタグ（`labels.rs`、`[labels]`）: フォルダごとの `.vw-labels.json` に、画像（ファイル名で引く）の
  ラベルを持つ（フォルダ自身には付けない）。必要になったフォルダから読み、変えたらすぐ書く（隣に書いてから置き換える）。
  書き込めないフォルダは設定フォルダの `labels/` に置く。キー操作（↑ ↓ 1〜9）はタグ付けモードの間だけ働く
  - 絞り込みと書き出し（`export.rs`）: `Filter`（すべて / フラグ / フラグなし / タグ）をツリー・画像送り・
    フォルダの読み込み・スライドショーに効かせる。変えたときは読み込んだフォルダのスロットも並べ直し
    （単体のスロットは合う画像だけに、フォルダスロットは一番近い合う画像に移すか空にする）。左の列のボタンで順に切り替える。書き出しはコピー（別スレッド、既存のファイルは上書きしない）と
    CSV / JSONL の一覧
- ドラッグ＆ドロップでの移動・コピー（`transfer.rs`）: 画像のスロットのヘッダをツリーのフォルダかフォルダのスロットへドラッグする
  （画像の上のドラッグはパンに使うため）。egui のアプリ内ドラッグで、OS へのドラッグはしない。Ctrl でコピー、移動は確認してから。
  同じ名前のファイルがあれば何もしない。ラベルも移した先に付け直す。展開した ZIP の中へは入れず、中からはコピーだけ。
  エクスプローラなどからのドロップは、そのフォルダへ移る（ファイルならそのフォルダへ移ってその画像を選ぶ）
- 自動リロード（`watch.rs`、`behavior.auto_reload`）: ツリーで開いているフォルダと、スロットに出している画像の
  フォルダを OS の通知（notify クレート、非再帰）で監視する。ファイルごとに 300ms 静かになるまでまとめてから
  反映し、コピー途中のファイルを読まない
  - 新しい画像: ツリーを読み直す（既存の項目は残して開閉状態を保つ）。最後の画像を表示していたスロットだけ、
    新しい画像に移る（スロットを 1 つだけ出しているとき＝最大化か 1x1 は、どこを見ていても移る）。
    フォルダスロットは並びを読み直す
  - 消えた画像: 表示していたスロットはその次の画像を出す
  - フォルダの読み込みで 1 枚 1 スロットに並べたスロット（`Slot::from_folder`）は中身を差し替えず、
    新しい画像のスロットをそのフォルダの最後のスロットの後ろに足し、消えた画像のスロットを閉じる
  - 今いるフォルダ（`VwApp::current`）は、画像がなくても監視する。空だったフォルダに画像が来たら
    スロットを作って出し、サブフォルダや ZIP が増減したらフォルダのスロットを足したり閉じたりする
  - 開いたフォルダのスロット（`SequenceKind::Subtree`）は並びを読み直さず、増えた画像を後ろに足し、消えた画像を除く
  - 表示中の画像の上書き: 倍率と位置を保ったまま読み直す
  - フォルダを読み込み中と、スライドショー中のスロットは並びを変えない
- フォルダの移動（cd）: エクスプローラのように、ツリーにはフォルダ（ZIP などの仮想のフォルダを含む）だけを出し、
  ツリーでクリックしたフォルダの中身をスロットに並べる（`VwApp::cd`）。開閉は ▶ だけで行う
  - 並べる順はサブフォルダ → ZIP → 画像。サブフォルダと ZIP は「フォルダのスロット」（`Slot::folder`）で、
    初めはアイコンと名前だけを出す。ダブルクリックで中の画像を読み込み（サブフォルダがあれば 1 回確認して
    全階層）、ヘッダ右の矢印か Enter でその中へ移る。Backspace で 1 つ上へ
  - Enter は「最大化」と同じ操作に割り当て、フォルダのスロットなら移動、画像のスロットなら最大化にする。
    キーの割り当ては操作ごとに重ならない決まりなので、別の操作にすると同じ Enter を割り当てられないため
  - 画像は別スレッドで読む（`autoload.rs`）。`tree.load_into` で、画像ごとに 1 スロットか、まとめて 1 スロットかを選ぶ。
    `tree.other_load_modifier`（既定 Alt）を押しながら移ると逆の入れ方になる
  - 区切り（既定 500 枚）ごとに続けるか確認する
  - フォルダを辿るのは別スレッド。先読みは 256 件までにして、確認で止まっている間に走査が進みすぎないようにする
  - ツリーのハイライトは今いるフォルダ。ツリーの外で移ったとき（Backspace など）は、そこまで親を開いてスクロールする
- 左端に固定幅（34px）のツール列。Browse / Pan / Zoom / Pixel probe / Measure と、スロット追加・設定を置く。
  Browse 以外はまだ機能がなく、押せない状態で表示している

## 見た目（`crates/vw-app/src/theme.rs`）

- プロ向け画像編集ソフトのような、灰色基調・1px の細線で区切る画面。影と角丸はほぼなし
- 面の色は色相のない灰色にして、画像の色の見え方に影響させない
- ダーク（濃い灰色）とライト（明るい灰色）の 2 組を egui に登録し、既定は OS の設定に従う
- 「Compact panels」で余白を egui の既定より詰める
- アイコンは Phosphor のアイコンフォント（`egui-phosphor`, MIT）を本文フォントの代替として組み込む

## 設定（`settings.rs` / `settings_ui.rs` / `keymap.rs`）

- 設定ファイル: TOML。Windows は `%APPDATA%\vw\settings.toml`、Linux は `$XDG_CONFIG_HOME/vw/settings.toml`
  （なければ `~/.config/vw/settings.toml`）
  - 書かれていない項目は既定値。ファイルがなければ作らず、最初に設定を変えたときに作る
  - 設定画面で値を変えるたびに保存し、外部エディタで書き換えられたら（1 秒ごとに更新時刻を確認）読み直す
  - TOML として読めないファイルは無視して今の設定（起動時なら既定値）で動く（エラーはログに赤字）
  - 値が壊れた項目は、その項目だけを既定値にする（`toml_reader.rs` で項目ごとに読む）。
    serde で全体を構造体に読むと 1 項目の型違いでファイル全体が使えなくなるため
  - `[keys]` は操作ごと。1 つでも読めないキーがある操作は既定のキーに戻す。重複は、利用者が変えた操作を
    既定に戻して解消する
  - 壊れていたファイルを最初に上書きする前に `settings.toml.bak` へ写す
- 設定画面: メイン領域（ツール列より内側）を置き換える。VSCode と同様の検索で絞り込み
  - 項目は「設定ファイルのキー・題・説明・編集部品」の表（`settings_ui::ITEMS`）で定義し、表から画面を組み立てる
  - 検索は空白区切りの語がすべて、キー・英語・表示中の言語の題と説明のどこかに含まれるもの
- ホットキー: `[keys]` に `操作名 = ["キー", ...]`。1 操作に複数キー可、1 キーは 1 操作だけ
  - 設定画面で「+」→ 実際にキーを押して登録。Esc で取り消し。修飾キー単独は無視
  - 別の操作で使用中のキーは登録させない。OS がよく使うキー（Alt+F4、Ctrl+Alt+T など）は登録できるが警告を出す
  - Ctrl+C / X / V は egui がキーではなくコピー等のイベントとして届けるため、割り当て不可
  - テキスト入力中は Ctrl / Alt 付きのキーだけを実行する

## 終了時の状態（`state.rs`）

- 設定ファイルと同じフォルダの `state.toml`。利用者が書く設定と、アプリが毎回書き換える状態を分ける
- ウインドウ: 最小化・最大化していないときの外枠の位置と内側の大きさ（物理ピクセル）、拡大率、最大化の有無、
  保存時のモニタ構成（各モニタの範囲と拡大率）。終了時（`on_exit`）に保存
  - 起動時、モニタ構成が保存時と同じなら最初のフレームで位置を送り、移動先の拡大率が反映されてから大きさを送る。
    違えば OS 任せ。Wayland では位置を取得・指定できないので大きさだけ
  - 項目は組で意味を持つので、1 つでも壊れていればウインドウ全体を OS 任せにする
- フォルダツリー: 開いていたフォルダのパスと、移っていたフォルダ。起動時に開き直し、移っていたフォルダへ移る
  （起動時にフォルダやファイルを渡したときはそちら）。消えたフォルダは飛ばす。展開した ZIP の中は保存しない
- 拡大率の違うモニタ間の移動で大きさが変わる件は egui / winit 側の挙動で、vw では対処していない

## 言語（`i18n.rs`）

- 既定は英語。設定で日本語に切り替える（再起動不要）
- 英語の文言を鍵にした表で日本語訳を引く。訳がなければ英語のまま
- 日本語フォントは日本語向けのものだけを候補にする。漢字は日中で同じ文字コードだが字形が異なり、
  中国語フォント（Noto Sans CJK SC、WenQuanYi など）を使うと中国風の字形になってしまうため
- ログの文言は英語のまま（調査時に検索しやすいように）
- メタデータはアクティブなスロットの画像を表示。アクティブなスロットが読み込み中は直前の表示を保つ
  （スロット追加のたびに「画像なし」を挟むと、まとめて開くときに点滅して見えるため）
- ログには読み込み・デコード・変換・テクスチャ転送の時間と、起動から最初の描画までの時間を出す

## 速さのための方針

- デコードと表示用変換は UI スレッド外で行う
- 日本語フォント（システムフォント）はバックグラウンドで読み込み、起動を待たせない
- フォルダツリーは開いたときに初めて読む
- リリースビルドは thin LTO・codegen-units=1・panic=abort
